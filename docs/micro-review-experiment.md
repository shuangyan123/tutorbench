# Micro-Review promotion experiment v1

Status: local implementation for acceptance only. No push, merge, deployment,
public campaign, analytics collector, or real participation data in this task.

## Audit and minimum design

The site is generated by `src/cli/website-build.ts`, with shared chrome in
`src/site/html.ts`, static English and `/zh-cn/` counterparts, and exact build-time
copy in `src/site/locale-copy.ts`. `website/src/teachometry.css` owns the shared
visual tokens, header, themes, controls, focus styles, and mobile shell.
Existing website tests cover routing, localization, public-data isolation, and
artifact completeness. No participation analytics or collector was found in the
public site. The shared script stores only an optional theme preference.
The Community page describes a future Reviewer program; applications and the
real campaign remain closed. Micro-Review links to this existing informational
entry without opening intake or connecting to the private Reviewer service.

Routes: `/micro-review/` and `/zh-cn/micro-review/`. Direct links can be shared
after a separately authorized launch; the homepage and navigation are unchanged.
The page inherits the existing Teachometry shell and theme tokens. Its stylesheet
and small interaction script load only on this route. No dependency is added.

Flow: read one constructed fraction dialogue -> choose basically suitable,
has a teaching problem, or not sure -> submit -> read the same short authored
analysis -> optionally explore the independent Reviewer plan. All three choices
are welcome; there is no participant score, vote tally, full rubric, enrollment,
login, free-text field, or request for personal details. Approximately 60 seconds
is a design target, not a measured completion-time claim.

The student proposes `1/3 + 1/4 = 2/7`; the constructed AI reply incorrectly
confirms adding numerators and denominators. Analysis explains `7/12` and a
next teaching step using twelve equal pieces of the same whole. Both dialogue
and explanation are authored demonstration copy translated for this page,
not captured model output, a canonical TutorEval case, or evaluator evidence.

## Privacy and evidence boundaries

- A native labeled radio group is required. Submission is intercepted locally;
  only then does the result become visible and its heading receive focus.
  Controls lock after completion. Reloading starts a new experience.
- The choice lives only in the current document. There is no fetch, beacon,
  POST, answer in URL/history, cookie, local/session storage, database, export,
  identity, fingerprint, or participant linkage added by Micro-Review.
  Browser back/forward caching may restore the displayed document.
- The shared optional theme preference continues to use existing localStorage;
  no judgment is written there. The hosting provider can still process ordinary
  asset/page requests and access logs under its own policies.
- The Reviewer link is same-site and does not transmit the choice or enroll
  anyone. Applications remain closed. Public experience must never enter Expert
  Review imports, human reference data, benchmark scores, calibration, evaluator
  results, or validity claims. No formal review contract is instantiated.
- JS failure leaves the form hidden and a localized enable-JavaScript notice
  visible, so a native fallback submission cannot leak an answer into a URL.
  No-JS users can still read the constructed conversation and public site.

## Participation measures: proposed, collection disabled

No real participant counts, success rates, answer distribution, or Reviewer
recruitment results are available. Browser QA is implementation evidence only.
For this smallest uninstrumented launch, reach can be estimated from existing
hosting aggregate traffic **if available**; access logs cannot determine choices,
completions, or Reviewer-link clicks. Do not infer these from page views.

If measurement is subsequently authorized, use one existing hosting-supported
cookieless aggregate event collector rather than a custom backend. Define only
the following allowlisted events for `micro-review-v1`, with UI locale:

| Event | Trigger and counting boundary |
| --- | --- |
| `view` | Once per visible page instance; wait until a prerendered page activates. |
| `start` | First actual radio selection, once per instance. |
| `complete` | First valid local submission, once per instance. Optional elapsed bucket from visible view: `under_30s`, `30_to_60s`, `over_60s`. |
| `reviewer_interest` | First click on the revealed Reviewer link, once per completed instance. |

Do not transmit the selected judgment, text, full URL/referrer/query string,
precise timestamp, IP, user agent, device ID, or any persistent/session identifier.
Client-side event IDs are not needed: deduplication is in memory. A collector
unavoidably receives transport metadata; it must discard it before persistence,
disable identifying access logs, and retain only daily event totals for a short
declared period (proposed 30 days). Check that capability and the hosting/privacy
terms before enabling collection. If it cannot satisfy these requirements, keep
measurement disabled. Collector failure must never prevent local completion.

Proposed definitions (all from the same instrumented version and time window):

- Reach: visible `view` events; these are page instances, not unique people.
- Start rate: `start / view`; completion rate: `complete / start`.
- 60-second target: completions with elapsed bucket at most 60 seconds divided
  by completions with a recorded bucket. Report missing buckets separately;
  start the timer when the page becomes visible, not during prerender.
- Optional interest rate: `reviewer_interest / complete`. This measures interest
  in program information, not applications, accepted Reviewers, or review quality.

Zero denominators mean unavailable, not 0%. Reloads and locale changes create
new instances; repeat visitors, bots, blockers, and background-tab time limit
interpretation. Do not pool instrumented and uninstrumented traffic. An initial
small voluntary usability sample can assess the one-minute target separately,
with consent and clearly labeled qualitative feedback; no results are claimed.

## Acceptance and remaining limits

Run typecheck, lint, full tests, build, the deterministic benchmark command,
website artifact smoke, and `git diff --check`. Browser QA must exercise all three
choices in English and Chinese at desktop/mobile sizes, keyboard-only selection
and submission, focus on analysis, optional link navigation, reload, theme,
missing-selection validation, no-JS behavior, and no answer network/storage/URL
side effects. Compare baseline output for home, Methodology, case pages, and the
four public-data JSON files; synthetic demonstration copy must not enter them.

Accessibility uses native fieldset/legend/radios, visible focus and labels,
minimum 48px option targets, math descriptions, a completion status, and a
focusable result heading. Automated browser accessibility snapshots are useful
evidence, but do not replace an actual NVDA/VoiceOver user check. This iteration
does not prove a real newcomer's completion time or promotion effectiveness.

Local verification on 2026-10-09:

- Typecheck and lint passed. Full tests: 684 passed, zero failed/skipped,
  including eight new Micro-Review tests. Build and website artifact smoke
  passed: 191 files and 68 required paths.
- Chrome browser QA: 45 passed, zero failed, zero console warnings/runtime
  errors or failed requests. English/Chinese and widths 1440, 390, and 320
  covered the participation flow; keyboard, reload, privacy side effects,
  static language switching, dark/reduced-motion/forced-color modes, no-JS
  behavior, and existing page regressions were exercised.
- All 187 pre-existing generated website files matched the main baseline
  byte-for-byte, including every case page and all four public JSON artifacts.
  The four additions are two localized HTML pages and the page's CSS/JS.
- `npm run benchmark` exited normally, but its 48 synthetic cases were
  `judge_unavailable`, with `judge: null` and no overall score. This is an
  unresolved/no-score run, not evidence that teaching quality passed.
- Actual NVDA/VoiceOver, Firefox/Safari, real newcomer timing, live hosting
  privacy policies, and promotion effectiveness remain unverified.
