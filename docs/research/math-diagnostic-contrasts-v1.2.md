# 数学作答对照与独立盲审材料 1.2.0

本研究附录固定在 1.1.0 的八道数学任务。它包含 24 段合成作答：6 段逐字取自原有项目案例，18 段为本次编写的反事实对照。每题有一段充分的参考作答和两段探针。每段分别记录回答的结论、论证、可检查的数学事实、两种可能解释和不得推出的能力判断。拟复核的归因陈述中，作者分别将 8 条标为可直接观察、8 条标为与书面步骤冲突、8 条标为证据不足。这些是构造对照时的预期；48 个竞争解释均待独立复核。

## 八题中的可证伪区别

| 题目 | 可核查的对照 | 待复核的解释边界 |
|---|---|---|
| 相切 | 两段都答 m=0；一段用半径垂直切线，另一段误称过顶点就相切。m=1 时另有交点 (−5,0)。 | 解联立方程是可选方法。答对斜率不能补全唯一性证明。 |
| 两个不同正根 | 判别式给出两个分支；取 a=−3 即可驳倒“两支都使根为正”。只报 a>2 与完整取交集的结果相同。 | 根数和符号应分别检查。短答看不出使用了韦达还是根公式。 |
| 分式方程 | 约分得到的候选 1 使原分母为零。原案例最后是提问。另一段正确答无解，却错误声称所有输入都使分母为零。 | 可判断候选不合格；无法判断提问者最终会接受它，或不会因式分解。 |
| 基本不等式 | (x−1)²/x 的符号给出完整解；只论证 x>0 上成立，没有解释对负数的断言。取 −1 可直接反驳。 | 使用其他证明、缺少一步理由、误用定理前提须分别记录。 |
| 连续百分比 | 一段使用 240 为第二次基数并正确算出折扣 48，最后写成 240−48=202；另一段认为涨跌相抵。 | 写错最后一行不足以定位借位或转抄失误，却足以反驳“第二次仍按 200 算”。 |
| 方程组相容性 | 系数成比例，右端不成比例。比较两条平行线的截距即可证明无解。 | 秩非必用工具；原提示已经提及答案键，单报无解无法识别方法。 |
| 数表建式 | 把两列互换后所得 x+2y=2 确实通过抄出的两点，却不经过原表的两点。另一段只给同一错误式。 | 只有显式抄点的作答提供了坐标转换的证据。 |
| 坐标图建式 | 换轴后写 y=2 与正确读点后把 2/0 算成 0 是两种可区分的错误。原图确定 x=2。 | 共同操作为建直线方程；竖直线没有有限斜率，图象误读也可能与代数方法并存。 |

完整作者视图保存原题、UTF-8 题干摘要、参考解、替代方法、原条款位置与指纹、概念定义标签、表示及论证要求。候选修订保留在本附录。八题与 14 条任务关联仍按 1.1.0 重放。历史 Wrong Diagnosis 校准样例 `target-diagnosis-incorrect-diagnosis` 针对 Tutor 作出了错误归因；此处复用其“断言错误与缺少诊断有别”的界线。六道可逐字复用的数学题来自既有 Scenario vNext 合成学习者发言；语言样例没有移作数学作答。正确结果配错误理由沿用 `correct-answer-wrong-reasoning-001` 的对照方式。[原任务与建式图表](math-geometry-task-evidence-v1.1.md) · [既有专家盲审协议](../case-system-vnext-expert-review.md)

## 离线重放与交接

构建后在仓库根目录运行下列命令。无子命令时输出作者视图。导出包内含 `packet` 与空白 `template`，`manifest` 是协调人持有的源记录对应表。导入文件仅取填写后的模板对象，使用 UTF-8 JSON。命令读取本地文件并输出到标准输出。实际材料应在仓库外分别保存。

```sh
npm run build
node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts
node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts export mathematics reviewer-a
node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts export construct reviewer-a
node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts export attribution reviewer-a
node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts manifest attribution reviewer-a
node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts import attribution reviewer-a submission.json
```

为 `reviewer-b` 分别重复三个导出。每个维度、席位均有独立包指纹与不透明项目 ID；同维度的集合指纹绑定同一份作者源记录（包括原题、答案、候选关联、条款与解释）。既有专家盲审的指纹与导入绑定检查提供版本、席位、任务全集和一对一匹配。新附录只扩展判断词汇与材料格式。导入成功仅表示提交结构完整且绑定了正确的包。

| 盲审维度 | 每人独立判断单位 | 可见材料与判断问题 |
|---|---:|---|
| 数学正确性 | 32 | 八份参考推导和二十四份作答以同一种形式呈现。独立解题后，判断呈现的推理是否足以支持所报结论，指出限制或反例。 |
| 条款与构念 | 14 | 一题的一个候选节点为一项，附题干、条款原位置和能力要求。检查来源的适配范围、概念与解法角色，以及是否过度要求一种表示或方法。 |
| 诊断归因 | 24 | 原题、单段合成作答和一条待检验陈述。找出支持或反驳它的具体步骤，提出竞争解释，并标出证据不足之处。 |

三个包均隐藏作者判定、失败模式、其他审核者意见与协调人对应表。参考推导自身在数学包中也是待检验的材料。原有 Tutor 案例中的提示请求、已有尝试或答案键线索保留原貌；审核对象限于书面数学证据。源文件公开意味着技术上无法保证人员盲态，协调人须记录先前是否读过作者材料及发生的揭盲。

## 独立性、分歧与外部依赖

1. 经另行授权，由协调人核验两位不同的数学教育或数学测评专业审核者，有相关学段经验，未参与本次材料编写，彼此独立。分别分配匿名席位；真实身份、资历、利益冲突和接收记录保存在授权的私有环境。当前两个席位均未分配。
2. 先独立锁定数学判断，再锁定条款与构念判断，最后评归因。每项填写 `supported`、`partial`、`unsupported` 或 `insufficient-evidence`，并写出理由、替代解释和不确定处。前者表示所呈现工作或主张得到充分支持；部分支持须标明是哪一部分。拒绝、保留或挑战题目、参考解和标注都可在理由中记录。
3. 协调人从冻结版本重建各包。分别导入、核对席位与指纹，并在私下确认真实独立身份与锁定顺序。只有二人均有合格提交后，才用对应表按稳定源项目配对。对每个维度单独报告四类决定的交叉计数、同判项数和配对分母。同判比例为同判项数除以该维度完整配对数，包含双方都选证据不足的项；另外列出这些项数。单人、模拟或不完整提交无独立一致率。不能由同判推算诊断准确率。
4. 保留两份原始决定及理由。由另行授权的裁决者对分歧记录依据、所用版本和裁决，或将其留作未解决；先报告裁决前的一致性。此版本没有人类提交、裁决或学习者结果。通过导入、相同决定或自动化验算均不会生成 Gold、已审核标签或评测分数。

如果以后研究真实作答，须另行取得授权、必要同意和适龄保护，限制用途、最小化采集、去标识化、限定访问和保留期限。此版本只用项目合成素材。#365 的 24 条既有 Eval/Health 关联与 #109 的双语分数题评审各有其范围。

### 重放证据边界

运行 `node dist/src/cli/exam-specifications.js --requirements --diagnostic-contrasts evidence` 可查看同一批 24 段合成作答的精简证据。每行给出可观察事实，并分别记录结论和论证。只有作者标为可从书面步骤核实的陈述才进入 `supportedStep`；与作答冲突或证据不足时该字段为 `null`。所有行都保留竞争解释，单份作答的因果归因均为 `insufficient-evidence`。此命令仅重放冻结样例中的作者标注。
