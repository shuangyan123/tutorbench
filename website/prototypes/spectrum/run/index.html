Run workflows运行工作流

01 / 05

Get started (provider-free)开始使用（无需服务提供方）

Clone the repository and run the deterministic Quickstart.

克隆仓库并运行确定性 Quickstart。

tutorbench · quickstart

# 1. Clone the repository
git clone https://github.com/shuangyan123/tutorbench.git
cd tutorbench

# 2. Install dependencies
npm ci

# 3. Run the Quickstart (no API key)
npm run quickstart
  • Repository main · Node 24仓库 main · Node 24
  • Runs locally without an API key无需 API key 即可本地运行
  • Uses 4 fixed cases from tutor-eval-v0.1@0.1使用 tutor-eval-v0.1@0.1 中的 4 个固定案例
  • No Judge, no network connection无需 Judge，无需网络连接
  • Deterministic checks (no official score)确定性检查（不产生正式分数）
  • Not leaderboard eligible不具备排行榜资格

A development/smoke demonstration with no overall score; Quickstart does not weaken the canonical benchmark boundary.

这是不产生总分的开发/冒烟演示；Quickstart 不会削弱标准基准的边界。

Published 0.1.0 · Node 22已发布 0.1.0 · Node 22Historical CLI with Quickstart; Tutor Health requires the Node 24 repository.历史 CLI 包含 Quickstart；Tutor Health 需要 Node 24 仓库源码。

npm install tutor-benchmark@0.1.0npx --no-install tutorbench quickstart

02 / 05

Diagnose an external Tutor in real-world scenarios在真实场景中诊断外部 Tutor

Run the repository-only, finding-first Tutor Health workflow against an HTTP Tutor.

使用仓库专有、以发现项为先的 Tutor Health 工作流评测 HTTP Tutor。

tutorbench · tutor health

node dist/src/cli/tutorbench.js health \
  --http https://partner.example.com/respond \
  --suite productive-struggle-intervention-v0.1 \
  --tutor-provider partner \
  --tutor-model production \
  --prompt-version v17 \
  --output artifacts/partner-pilot
  • Writes evaluation.json, health-report.json, and health-report.txt写出 evaluation.json、health-report.json 和 health-report.txt
  • Records Tutor provider, model/config, and prompt version provenance记录 Tutor 服务提供方、模型/配置和 prompt 版本来源
  • Reports Tutor Health Score, explicit coverage, Release Gate, Findings, and regression targets报告 Tutor Health Score、显式覆盖、Release Gate、发现项与回归目标
  • No-Judge runs stay UNRESOLVED and are marked as incomplete evidence无 Judge 的运行保持 UNRESOLVED，并标记为证据不完整

The current 13-scenario suite is an authored synthetic design artifact with partial health-dimension coverage; it is not a validated general tutor-quality or learner-outcome measure.

当前 13 情境套件是人工编写的合成设计产物，只覆盖部分健康维度；它不是经过验证的一般 Tutor 质量或学习结果测量。

03 / 05

Run the canonical benchmark运行标准基准

Use the current public dataset and preserve its fail-closed evaluator boundary.

使用当前公开数据集，并保留其 fail-closed 评估器边界。

tutorbench · benchmark

npm run benchmark
  • Current dataset: tutor-eval-v0.2a@0.2a.6当前数据集：tutor-eval-v0.2a@0.2a.6
  • 48 public cases in the canonical artifact标准产物中的 48 个公开案例
  • Judge-required criteria stay unresolved without an explicit Judge没有显式 Judge 时，需要 Judge 的标准保持未解决
  • No score is reported when required evidence is unavailable所需证据不可用时不报告分数

The canonical run is distinct from the four-case Quickstart and may report errors or no score without Judge configuration.

标准运行不同于四案例 Quickstart；没有 Judge 配置时可能报告错误或不产生分数。

04 / 05

Connect an external Tutor over HTTP通过 HTTP 连接外部 Tutor

Run the repository example, then send TutorTurnInput to POST /respond.

运行仓库示例，然后把 TutorTurnInput 发送到 POST /respond。

tutorbench · external tutor

python examples/http-python-tutor/server.py

tutorbench run --http http://127.0.0.1:8000/respond --limit 3
  • TutorTurnInput JSON in; { text, metrics? } JSON out输入 TutorTurnInput JSON；输出 { text, metrics? } JSON
  • Default request timeout is 30 seconds默认请求超时为 30 秒
  • External requests are not retried automatically外部请求不会自动重试
  • Product Tutor evidence remains separate from canonical model evidence产品 Tutor 证据与标准模型证据保持分离

The adapter evaluates the Tutor response at the edge; evaluator-only evidence stays inside TutorBench.

适配器在边缘评估 Tutor 回复；仅供评估器使用的证据保留在 TutorBench 内部。

05 / 05

Freeze and inspect evidence paths冻结并检查证据路径

Collect Product Tutor or canonical model responses, then evaluate a frozen corpus offline.

采集产品 Tutor 或标准模型回复，然后离线评估冻结语料。

tutorbench · advanced

tutorbench collect --http http://127.0.0.1:8000/respond --provider <provider> --model <actual-model-id> --prompt-version product-config-v3 --provenance external --limit 3 --output artifacts/product/product.json

tutorbench collect-model --http http://127.0.0.1:9000/generate --provider <provider> --model <actual-model-id> --limit 3 --output artifacts/real-model/model.json

tutorbench evaluate --corpus artifacts/real-model/model.json

# Export the semantic and canonical packets
npm run tutor:export-execution -- -- --case fraction-misconception-001
npm run tutor:export-cases

# Validate and replay a frozen corpus
npm run tutor:corpus:validate -- -- --corpus path/to/corpus.json
npm run benchmark:corpus -- -- --corpus path/to/corpus.json

# OpenAI Judge dry-run (no network)
npm run judge:openai -- -- --dry-run

# Frozen-corpus DeepSeek Judge subset
node dist/src/cli/tutorbench.js evaluate \
  --corpus artifacts/real-model/baseline.json \
  --limit 1 \
  --judge-deepseek
  • Product Tutor and canonical model collection are different paths产品 Tutor 与标准模型采集是不同路径
  • TutorExecutionPacket and TutorGenerationSpec identify canonical requestsTutorExecutionPacket 与 TutorGenerationSpec 标识标准请求
  • OpenAI Responses and DeepSeek Chat Completions are explicit Judge pathsOpenAI Responses 与 DeepSeek Chat Completions 是显式 Judge 路径
  • Canonical model collection uses baseline-native-default标准模型采集使用 baseline-native-default
  • Controlled optional generation parameters: none受控可选生成参数：无
  • Local artifacts remain preliminary, uncalibrated, and not public本地产物仍属初步、未校准且不公开

Collection is not publication, calibration, or leaderboard eligibility; frozen evidence can be inspected and replayed offline. The baseline-native-default profile leaves optional temperature, reasoning, and seed controls unconstrained so provider-native behavior is not misrepresented as identical across vendors. tutor:export-cases is the semantic Tutor-visible adapter packet; tutor:export-execution is the canonical benchmark packet used to make model runs comparable. Neither packet includes evaluator-only annotations. The same benchmark does not imply that every provider exposes identical inference knobs.

采集不等于发布、校准或取得排行榜资格；冻结证据可以离线检查和重放。baseline-native-default 配置不约束可选的 temperature、reasoning 和 seed 控制项，避免将不同服务提供方的原生行为误称为一致。tutor:export-cases 是 Tutor 可见的语义适配器数据包；tutor:export-execution 是用于使模型运行可比较的标准基准数据包。两者均不包含仅供评估器使用的注释。使用同一基准并不意味着每个服务提供方都提供相同的推理控制项。

Current workflows use the Node 24 repository source. Published npm 0.1.0 requires Node 22 and includes Quickstart, but has no Tutor Health CLI or API. Check release channels and API boundaries 当前工作流使用 Node 24 的仓库源码。已发布 npm 0.1.0 要求 Node 22，包含 Quickstart，但没有 Tutor Health CLI 或 API。查看发行渠道与 API 边界

Our principle我们的原则

“Not just outputs, but evidence you can trust.”“不只是输出，更要有你可以信任的证据。”

We design TutorBench so benchmark conditions, evaluator boundaries, and artifacts can be inspected and reproduced. When evidence is unavailable, the system should fail closed rather than silently invent a valid score.

我们设计 TutorBench，是为了让基准条件、评估器边界和产物都可检查、可复现。证据不可用时，系统应停止评分并明确报告证据缺失（fail closed），而不是静默生成一个看似有效的分数。
